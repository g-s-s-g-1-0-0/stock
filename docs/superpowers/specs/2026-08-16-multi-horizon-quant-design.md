# 시간축 분리 퀀트 전략 및 백테스트 재설계

작성일: 2026-08-16
상태: 설계안 (승인 대기)

## 0. 이 문서를 쓰는 이유

기존 백테스트 결과를 신뢰할 수 없다는 문제 제기가 출발점이다. 체감상 20~30% 수익이
났어야 할 거래가 백테스트에서는 +1~2% 또는 손절로 집계된다.

코드를 조사한 결과, 원인은 "종목이 너무 많아 평균이 희석됐다"가 **아니었다**.
측정 정의가 서로 다른 네 가지 값을 같은 것으로 비교하고 있었다.

| 원인 | 근거 위치 | 효과 |
|---|---|---|
| 헤드라인이 종가 수익(`mean20`)인데 사람이 보는 값은 최대 평가익(`mfe20`) | `common_bottom_event_study.py:296-307` vs `:163-172` | 가장 큼 |
| 일부 표가 절대수익이 아니라 유니버스 대비 초과수익(`ex20`, `d20Excess`) | `washout_rules.py:41-51`, `bottom_rebound_study.py:544-547` | 큼 |
| 같은 일봉에서 목표·손절 동시 터치 시 **무조건 손절** 처리 | `bottom_rebound_core.py:963-970` | 큼 |
| 모듈마다 수수료 유무가 달라 표끼리 비교 불가 | `ma200_macd_golden.py:199-202`(수수료 없음) vs `bottom_rebound_core.py:877`(있음) | 중간 |
| 신호 강도 층화 없이 전부 한 평균에 뭉갬 | 전 모듈 공통 | 중간 |
| 진입가가 항상 D+1 시가 (실제로는 종가·장중 지정가 체결) | 전 모듈 공통 | 중간 |
| 대형주 137종목·관심종목 한정, 생존편향 미보정 | `backtest_qqq_block_v2.py:29-48` | 중간 |

따라서 이 설계의 1차 목표는 새 전략이 아니라 **잣대의 복구**다. 잣대를 고치지 않으면
새 전략도 똑같이 못 믿는다.

## 1. 확정 사항

### 1.1 시간축 정의

| 시간축 | 보유 | 목표 | 검증 데이터 | 신뢰도 라벨 |
|---|---|---|---|---|
| 초단타 | 당일 장중 진입·마감 전 청산 | ATR 기준 (참고: 2~3%) | 1분봉 30일 + 전진 수집 | 탐색 (결론 금지) |
| 단타 | 1~5 거래일 | ATR 기준 (참고: 5~10%) | 1시간봉 730일 + 일봉 1999~ | 중간 |
| 스윙 | 2~8주 (10~40 거래일) | ATR 기준 (참고: 20~30%) | 일봉 1999~ | 높음 |

### 1.2 목표·손절은 % 고정이 아니라 ATR 배수

고정 %를 쓰면 저변동성 종목에서는 목표에 도달할 수 없고, 고변동성 종목에서는 너무 쉽게
도달한다. 체감 20~30%가 나온 종목은 거의 확실히 고변동성 종목이었고, 같은 -10% 손절을
저변동성 종목에 적용하면 사실상 손절이 걸리지 않는다. 이 둘을 한 평균에 넣으면 결과가
무의미하다.

기준: 진입 시점 ATR(20)의 종가 대비 비율(`atrPct`)을 사용한다.

| 시간축 | 목표 | 손절 | 최대 보유 |
|---|---|---|---|
| 초단타 | 1.0 × ATR(15분,14) | 0.7 × ATR(15분,14) | 당일 마감 강제 |
| 단타 | 2.0 × ATR(20) | 1.0 × ATR(20) | 5 거래일 |
| 스윙 | 4.0 × ATR(20) | 2.0 × ATR(20) | 40 거래일 |

참고용으로 "이 설정이 %로는 몇 %였는지"를 거래마다 원장에 기록해, 사용자 체감치와 직접
대조할 수 있게 한다.

### 1.3 유니버스

미국 상장, 유동성 게이트 통과 전종목 (약 1,000~2,000종목).

- 시가총액 ≥ 3억 달러
- 20일 평균 거래대금 ≥ 2천만 달러
- 주가 ≥ 5달러 (동전주 제외)
- ETF·ADR·SPAC·우선주 제외

게이트는 **매월 말 시점 데이터로만** 판정하고 다음 달에 적용한다 (look-ahead 차단).

### 1.4 생존편향 처리

현재 상장 종목 리스트로 과거를 돌리면 결과가 위로 왜곡된다. 처리 순서:

1. Wayback Machine에 보관된 `nasdaqlisted.txt` / `otherlisted.txt` 월별 스냅샷을 수집해
   시점별 상장 목록을 복원한다.
2. 복원되지 않는 구간은 결과에 `survivorshipBias: uncorrected` 플래그를 붙이고, 보정 전
   결과를 최종 결론으로 쓰지 않는다.
3. 폐지 종목도 티커를 알면 Yahoo에서 과거 시세가 나오는 경우가 많으므로 최대한 회수한다.

### 1.5 비용 가정 (전 모듈 통일)

| 항목 | 값 |
|---|---|
| 수수료 | 편도 5bp (왕복 10bp) |
| 슬리피지 (시가·성립가 주문) | max(2bp, 0.05 × atrPct) |
| 슬리피지 (지정가 체결) | 0 (대신 미체결 처리) |
| 초단타 추가 스프레드 | 3bp |

전 백테스트가 같은 상수를 공유한다. 수수료 없는 표는 더 이상 만들지 않는다.

## 2. 데이터 계층

### 2.1 확보 방침

| 계층 | 봉 | 소급 | 대상 | 연간 용량 |
|---|---|---|---|---|
| L0 | 일봉 | 1999~ | 전 유니버스 | 기존 `.bt_cache` 흡수 |
| L1 | 1시간 | 730일 (무료 최대) | 전 유니버스 | 약 180 MB |
| L2 | 5분 | 60일 + 전진 수집 | 전 유니버스 | 약 100 MB |
| L3 | 1분 | 30일 + 전진 수집 | 유동성 상위 200 + 신호 발생 종목 | 약 500 MB |

Yahoo 인트라데이 소급 제한(1분 30일, 5·15·30분 60일, 1시간 730일)이 계층을 나누는 이유다.
1시간봉 2년치는 지금 즉시 확보되므로 **단타는 오늘부터 검증 가능**하고, 초단타는 1분봉을
쌓아야 하므로 6~12개월 뒤에야 통계가 성립한다.

### 2.2 저장

`data/intraday/{interval}/{YYYY-MM}/{ticker}.parquet` — 월별 파티션, gitignore 대상.
`.bt_cache`의 pickle은 유지하되 신규 코드는 parquet만 읽는다.

### 2.3 품질 검사 (수집 파이프라인 필수)

Yahoo 인트라데이는 봉이 간헐적으로 누락되고 액면분할이 소급 반영되지 않는다.

1. 세션당 기대 봉 수 대비 결측률 5% 초과 시 해당 종목·일자를 `quarantine`으로 격리
2. 일봉 대비 인트라데이 종가 정합성 검사 (0.5% 초과 이탈 시 격리)
3. 분할 이벤트 발생 시 해당 종목 인트라데이 전 구간 재수집
4. 격리된 데이터는 백테스트에서 제외하고, 제외 비율을 리포트에 명시

### 2.4 펀더멘털 (중요한 제약)

`valuation.json`은 최신 스냅샷만 덮어쓰므로 **과거 시점 PER/PBR을 복원할 수 없다**.
시점 정합성 있는 밸류 데이터는 `data/history/*.jsonl`의 57종목·83일이 전부다.

따라서 가치 데이터는 백테스트 알파로 쓸 수 없다. 과거에 현재 스냅샷을 적용하면 look-ahead다.
역할을 셋으로 한정한다.

- **V-1 부실주 배제 게이트**: 부채비율 과다 + 당좌비율 < 1 + 영업이익률 음수 + 매출 역성장이
  동시에 성립하면 후보에서 제외. 운용 시 실시간 적용, 백테스트 결과에는 미반영.
- **V-2 동시 신호 순위**: 같은 날 신호가 슬롯 수보다 많이 발생하면 Rule of 40, P/FCF,
  매출 YoY로 순위를 정한다.
- **V-3 실적발표 회피**: `earningsDate` ±2 거래일 신규 진입 금지. 과거 실적발표일은
  yfinance에서 종목당 수년치 확보 가능하므로 이 항목만은 백테스트 가능하다.

동시에 오늘부터 전 유니버스 밸류 스냅샷을 매일 PIT 로그로 적재한다. 12개월 뒤에는 가치
팩터도 백테스트 대상이 된다.

## 3. 신뢰 복구 장치 (이 설계의 핵심)

### 3.1 거래 단위 원장 (`core/ledger.py`)

모든 백테스트가 **동일 스키마의 거래 원장 CSV**를 낸다. 요약 통계는 원장에서 파생되며,
원장 없는 요약은 금지한다. 사용자가 자기가 아는 종목·날짜를 직접 찾아 검증할 수 있어야 한다.

| 컬럼 | 의미 |
|---|---|
| `strategy`, `ticker`, `signalDate` | 신호 (D 종가 확정) |
| `entryDate`, `entryPrice`, `entryMode` | 체결 (`nextOpen` / `limitPullback`) |
| `exitDate`, `exitPrice`, `exitReason` | 청산 (`target`/`stop`/`time`/`trail`/`censored`) |
| `holdingDays` | 보유 거래일 |
| `realizedRetGross`, `realizedRetNet` | 규칙대로 청산한 실현 수익 (비용 전/후) |
| `mfe`, `mfeDay`, `mae`, `maeDay` | 보유 중 최대 평가익·평가손과 발생일 |
| `retD1`, `retD5`, `retD20`, `retD40` | 고정 체크포인트 종가 수익 |
| `barrierAmbiguous`, `ambigResolvedBy` | 같은 봉 양방 터치 여부, 해결 근거(`hourly`/`unresolved`) |
| `retPessimistic`, `retOptimistic` | 모호 구간 보수·낙관 양쪽 값 |
| `atrPctAtEntry`, `targetPct`, `stopPct` | ATR 배수를 %로 환산한 값 |
| `universeRetSame`, `excessRet` | 동일 기간 유니버스 수익과 초과수익 |
| `signalStrengthDecile` | 신호 강도 십분위 |
| `regimeQqqPremium`, `vix`, `rsi`, `adx`, `bbWidth` | 진입 시점 국면·지표 |
| `feeBps`, `slippageBps` | 적용 비용 |
| `episodeId`, `dedupKept` | 에피소드 식별자, 중복 제거 후 채택 여부 |

### 3.2 한 거래를 네 가지 잣대로 동시 표기

요약표에 다음 네 값을 **항상 나란히** 놓는다. 지금까지 이 값들이 따로 보고돼 혼동이 생겼다.

1. 실현 수익 (규칙대로 청산)
2. 최대 평가익 MFE — 사용자가 화면에서 보는 값
3. 최대 평가손 MAE
4. 고정 체크포인트 D+5 / D+20 / D+40

"평균 실현 +2.1% / 평균 MFE +14.8% / MFE 상위 20% 중위 +31%"처럼 한 줄로 보이면,
체감과 백테스트가 왜 다른지가 즉시 설명된다.

### 3.3 장중 순서 모호성의 이중 집계

일봉에서 저가가 손절선을, 고가가 목표선을 모두 건드린 경우 실제 순서는 알 수 없다.
현재 코드는 무조건 손절로 처리해 결과를 체계적으로 낮춘다.

처리 방식:

1. 해당 거래를 `barrierAmbiguous = true`로 표시하고 **건수와 비율을 반드시 보고**
2. 전부 손절 처리한 `retPessimistic`과 전부 목표 처리한 `retOptimistic`을 **둘 다** 산출
3. 1시간봉이 있는 구간(2년)은 실제 순서를 해결해 `ambigResolvedBy = hourly`로 확정
4. 해결된 구간에서 실측 비율을 구해, 해결 불가 구간에 그 비율을 적용한 중간 추정치를 제시

모호 거래 비율이 15%를 넘으면 그 설정은 "일봉으로 검증 불가"로 판정하고 결론을 내지 않는다.

### 3.4 신호 강도 층화

신호를 만족한 정도에 따라 결과가 크게 달라지는데 지금은 전부 한 평균에 들어간다.
예: RSI 29와 RSI 12, 거래량 2배와 5배가 같은 취급을 받는다.

각 전략은 연속형 신호 강도 점수를 정의하고, 결과를 강도 십분위별로 표시한다.
실제 매매에서 고르는 것은 대개 최상위 분위이므로, 체감과의 괴리 상당 부분이 여기서 설명된다.

### 3.5 분포 보고 (평균 금지)

평균만 보고하지 않는다. 필수 항목:

- 십분위 분포, 사분위, 중위수
- 상위 10% 거래가 총수익에서 차지하는 비율
- 승률과 손익비 (평균 이익 / 평균 손실)
- 목표 도달률과 도달까지 걸린 일수 중위값
- 종목·연도 집중도 (상위 5종목 기여율 30% 초과 시 무효 판정)

### 3.6 진입가 이중 측정

같은 신호에 대해 두 가지 체결을 병렬 계산한다.

- `nextOpen`: D+1 시가 (확실히 체결, 보수적)
- `limitPullback`: D+1에 D 종가 × (1 − 0.5 × atrPct) 지정가, 미체결 시 당일 취소

`limitPullback`은 체결률을 함께 보고한다. 실제 매매가 이쪽에 가까울 것이므로, 두 값의
차이가 곧 "진입가 차이의 기여분"이다.

### 3.7 개인 매매로그 대조 리플레이

Supabase `user_settings.personal_trade_logs`와 `data/cache/trade-logs.json`의 실제 거래를
엔진에 그대로 태워, 거래별로 괴리를 분해한다.

출력: 거래마다 `내 실현 수익` vs `엔진 계산` 차이를 진입가 차이 / 청산 규칙 차이 /
보유기간 차이 / MFE-실현 차이로 분해한 표.

이것이 신뢰 복구의 최종 확인 절차다. 이 표에서 차이가 설명되지 않으면 엔진에 버그가 있다.

### 3.8 이벤트 스터디와 포트폴리오 2단 분리

- **1단 이벤트 스터디**: 자금·슬롯 제약 없음. 신호 자체의 통계적 우위를 측정. 개별 종목
  체감치와 비교할 때는 이 값을 쓴다.
- **2단 포트폴리오**: 슬롯 제한, 자금 배분, 동시 신호 경합 반영. 실제 자산 성장 추정에만 쓴다.

지금까지 이 둘이 섞여 보고돼 "신호는 좋은데 왜 수익이 안 나오나"가 구분되지 않았다.

## 4. 시간축별 백테스트 규칙

### 4.1 공통 규칙

- D = 신호 확정 종가. D 시점에 알 수 있는 정보만 사용.
- 에피소드 중복 제거: 종목당 1포지션. 단, 원시 이벤트 결과도 함께 보고.
- 검열 처리: 보유기간이 데이터 끝에 걸린 거래는 `censored`로 표시하고 별도 집계.
  각 D+N 지점의 표본 수를 항상 표기.
- 사후 정의 바닥은 별도 라벨로만 표기하고 매매 가능 신호로 취급하지 않는다.

### 4.2 스윙 (신뢰도: 높음)

데이터: 일봉 1999~현재.

청산 규칙 3종을 병렬로 측정하고 비교한다.

1. 고정 보유 20일 / 40일
2. ATR 배리어 (목표 4×ATR, 손절 2×ATR, 최대 40일)
3. 추적 청산 (최고가 대비 −2×ATR 이탈 또는 종가 < MA20)

필수 검증 항목:

- **시대 분할**: 1999-2007 / 2008-2012 / 2013-2019 / 2020-2022 / 2023-현재 각각 별도 집계.
  기존 백테스트는 2010년 이후만 봤다. 이것이 가장 큰 미검증 리스크다.
- **워크포워드**: 3년 학습 / 1년 검증 롤링. 학습 구간에서 고른 파라미터로 검증 구간을 평가.
- **파라미터 안정성**: 최적값 주변 ±20%에서 성과가 붕괴하면 과최적화로 판정하고 폐기.
- **다중검정 보정**: 시도한 파라미터 조합 수를 기록하고, "N개 중 최고"임을 명시.
  조합 수가 많으면 Deflated Sharpe Ratio를 적용.
- **집중도**: 종목·연도별 기여율.
- **생존편향**: 1.4절 절차 적용 여부 명시.

### 4.3 단타 (신뢰도: 중간)

데이터: 1시간봉 730일 (주), 일봉 1999~ (보조).

- 진입: D 종가 신호 → D+1, `nextOpen`과 `limitPullback` 병렬
- 청산: 목표 2×ATR(20), 손절 1×ATR(20), 최대 5거래일. **1시간봉으로 장중 순서 해결**
- 핵심 검증: 일봉 장기 결과와 1시간봉 2년 결과의 **일치성 검사**.
  일봉에서 성립하고 1시간봉에서도 성립하면 신뢰. 어긋나면 장중 경로 의존적이라는 뜻이므로
  일봉 결과를 폐기한다.
- 표본 요구: 최소 200 거래. 미달 시 결론 금지.

### 4.4 초단타 (신뢰도: 탐색)

데이터: 1분봉 30일 + 전진 수집. 표본이 성립하기까지 6~12개월 필요.

- 진입: 신호 봉의 다음 봉 시가 + 스프레드·임팩트 슬리피지
- 청산: 목표 1.0×ATR(15분), 손절 0.7×ATR(15분), 장 마감 강제 청산
- 1분봉 내부의 틱 순서도 알 수 없음을 명시. 봉 내 양방 터치는 3.3절과 동일 처리
- **비용 민감도 스윕 필수**: 왕복 비용 10 / 20 / 40 / 60bp에서 기대값 부호가 바뀌는 지점을
  찾는다. 초단타는 비용이 알파를 전부 잠식하는 것이 기본값이다.
- 지표: 거래당 평균이 아니라 **비용 후 거래당 기대값**과 **시간당 기대값**
- 표본 요구: 최소 300 거래. 그전까지는 어떤 결론도 내지 않는다.

## 5. 전략 후보

전부 기존 지표(`calculator/indicators.py`)와 국면 데이터(`calculator/market_regime.py`)로
계산 가능하다. 각 전략은 데이터 마이닝이 아니라 사전 가설을 갖는다.

### 5.1 스윙

**SW-1 국면 조건부 모멘텀**
가설: 모멘텀 프리미엄은 강세 국면에서만 안정적으로 나타나고 약세 국면에서는 역전된다.
조건: QQQ > MA200 이고 MA200 기울기 > 0 인 국면에서, 6개월 수익률 상위 10%,
52주 고점 대비 −15% 이내, ADX > 20.
신호 강도: 6개월 수익률 순위와 RS20의 결합 점수.

**SW-2 변동성 수축 돌파**
가설: 변동성 수축은 에너지 축적이며, 거래량을 동반한 돌파는 방향성 지속으로 이어진다.
조건: `BB_Width`가 60일 평균 대비 하위 20%인 상태가 5일 이상 지속, MA20 > MA60 > MA200,
52주 고점 −10% 이내, 돌파일 거래량 ≥ 20일 평균의 2배.
신호 강도: 수축 정도 × 거래량 배수.

**SW-3 공황 washout 반등 (기존 전략 재측정)**
가설: 시장 전반의 강제 청산이 개별 종목을 내재가치와 무관하게 눌러 단기 반등을 만든다.
조건: VIX ≥ 22 또는 QQQ MA200 이격 ≤ −5% 국면에서, 20일 신저가, RSI(14) < 30,
아래꼬리 비율 상위, 거래량 급증.
**기존 전략과 동일 조건을 새 잣대로 다시 측정하는 것이 목적이다.** 기존 결과를 못 믿는
문제를 직접 해소한다.

### 5.2 단타

**DT-1 강세 국면 과매도 되돌림**
가설: 상승 추세 안의 단기 과매도는 구조적 훼손이 아니라 일시적 수급 불균형이다.
조건: 종가 > MA200, RSI(2) < 5 (보조: RSI(14) < 30), 3일 연속 하락, 유동성 게이트 통과.
청산: 목표 2×ATR, 손절 1×ATR, 또는 종가 > MA5 시 청산, 최대 5일.

**DT-2 갭 하락 리버설**
가설: 뉴스 없는 갭 하락은 과잉 반응이며 장중 매수세가 유입된다.
조건: 갭 ≤ −4%, 전일까지 MA20 위 상승 추세, 개장 후 60분 내 시가 저점 미갱신
(1시간봉으로 판정), 실적발표일 아님.
청산: 1~3일.

### 5.3 초단타 (탐색)

**SC-1 개장 레인지 돌파**: 첫 30분 고가 돌파, 손절 = 첫 30분 저가, 마감 청산.
**SC-2 VWAP 회귀**: 시가 대비 −2% 이하로 이탈 후 VWAP 재돌파, 마감 청산.

## 6. 모듈 구조

중첩 패키지 대신 파일 하나가 한 가지 책임을 갖는 평면 구조로 구현했다. 파일 수가 적어
전체를 한눈에 읽을 수 있고, 현재 규모에서 디렉터리 계층은 이득이 없다.

```
quant/
  config.py            # 비용·ATR 배수·청산 정책·시대 구분 (단일 출처)
  data.py              # 일봉 로더, 유동성 게이트, 유니버스 수익률
  features.py          # 지표 패널, 시장 국면, breadth
  strategies.py        # SW-1/2/3, DT-1/2 정의 + 신호 강도 점수
  engine.py            # 체결 모델, 청산 시뮬레이션, 거래 원장
  metrics.py           # 4가지 잣대 동시 표기, 분포, 집중도
  validate.py          # 파라미터 안정성, 워크포워드, 포트폴리오
  collect_intraday.py  # 1h/5m/1m 계층 수집 + 품질 검사
  hourly_check.py      # 일봉 vs 1시간봉 일치성 검증
  run.py               # CLI
```

저장 형식은 parquet 대신 pickle을 쓴다. 시스템 파이썬이 외부 패키지 설치를 막고 있고,
`.bt_cache`가 이미 pickle을 쓰므로 형식을 통일하는 편이 낫다. 용량 차이는 미미하다.

미구현: 개인 매매로그 대조, 초단타 전략, 시점별 유니버스 복원. 초단타는 1분봉 표본이
쌓인 뒤로 미룬다.

기존 `research/strategy3`, `research/strategy4`는 건드리지 않고 남긴다. 신규 코드는
`quant/` 아래에만 쓰고, 두 계열의 숫자를 섞어 비교하지 않는다.

## 7. 단계별 진행

| 단계 | 내용 | 산출물 | 선행 조건 |
|---|---|---|---|
| P0 | 원장·지표 엔진 + SW-3 재측정 + 매매로그 대조 | 기존 전략의 신뢰 가능한 재측정 결과 | 없음 (일봉 기존 데이터) |
| P1 | 데이터 계층 (유니버스, 1시간봉 2년, 품질 검사) | parquet 데이터셋 | P0 |
| P2 | 스윙 SW-1·SW-2 + 전체 검증 스위트 | 시대 분할·워크포워드 결과 | P1 |
| P3 | 단타 DT-1·DT-2 + 1시간봉 일치성 검사 | 단타 검증 결과 | P1 |
| P4 | 1분봉 전진 수집 시작 + 초단타 탐색 | 6~12개월 후 판단 | P1 |

P0가 먼저인 이유는, 잣대를 신뢰할 수 있게 만들지 않으면 P2~P4 결과도 같은 이유로 못 믿기
때문이다. P0만으로도 "기존 전략이 정말 효과가 없는가"라는 질문에 답이 나온다.

## 8. 명시적 한계

1. 가치 팩터는 PIT 데이터가 없어 현재 백테스트 불가. 12개월 적재 후 가능.
2. 생존편향은 Wayback 복원이 실패하면 보정되지 않는다. 그 경우 결과는 상향 편향.
3. 인트라데이는 Yahoo 무료 데이터라 결측·분할 문제가 상존한다. 격리 비율을 항상 보고한다.
4. 1분봉 내부 틱 순서는 어떤 방법으로도 알 수 없다. 초단타 결론은 항상 구간 추정이다.
5. 한국 시장은 이번 범위에서 제외했다 (상한가·거래정지·생존편향 처리가 별도 작업).
6. 배당은 Yahoo 수정주가에 반영되지만 배당락 이벤트 로그는 저장하지 않는다.
